# Lean Doc Harness

**얇은 문서로 방향을 정하고, 작은 코드와 짧은 JSDoc으로 구현하는 개발 하네스.**
기능 중심 구조를 유지하고, 작업이 끝나기 전에 설명과 코드가 맞는지 한 번 확인합니다.

## 핵심은 네 가지

| 요소 | 역할 | 담을 내용 |
| --- | --- | --- |
| `AGENTS.md` | 어떻게 작업하는가 | 구조·읽는 순서·검증 기준 |
| 기능 문서 | 무엇을, 왜 만드는가 | 목적·흐름·중요한 동작·확인 조건 |
| JSDoc | 이 코드를 어떻게 이해하는가 | 책임·필요한 제약·부작용 |
| 갱신 훅 | 무엇을 다시 확인하는가 | 바뀐 코드와 관련 설명의 불일치 |

## 작업 순서

1. `AGENTS.md`와 해당 기능 문서를 읽습니다.
2. 유지할 동작과 완료 조건을 확인합니다.
3. 작은 책임 단위로 구현하고 필요한 검사를 실행합니다.
4. 훅의 점검 요청을 받으면 이번 작업의 문서·JSDoc 불일치만 고칩니다.
5. 변경 내용·검증·점검 결과를 보고합니다.

## 파일 구조

```text
AGENTS.md                    # 작업 규칙 원본
CLAUDE.md                    # 같은 규칙을 읽는 짧은 연결
docs/features/_template.md   # 기능 문서 양식
scripts/review-docs.mjs      # 종료 전 점검 훅 하나
.claude/settings.json        # Claude Code 연결
.codex/hooks.json            # Codex 연결
tests/                      # 훅 동작 검증
.github/workflows/check.yml  # 이 하네스의 검사
```

앱 코드는 `src/features/<feature>/`에 기능별로 모읍니다. 공통 코드는 실제로 재사용될 때 `src/shared/`로 옮깁니다.
계산·변환은 작은 모델 함수가 맡고, 상태·네트워크·DB 연결은 상위 코드가 맡습니다.
이 레포에는 앱 프레임워크나 상태 관리 라이브러리를 포함하지 않습니다.

## 새 프로젝트에 적용

1. Node.js 22 이상과 Git이 있는 프로젝트에 규칙·문서 양식·점검 스크립트를 복사합니다.
2. 사용하는 도구의 훅 설정을 추가합니다. 기존 설정이 있으면 `hooks.Stop` 항목만 합칩니다.
3. 기능 양식을 `docs/features/<feature>.md`로 복사해 채웁니다. 목표는 보통 20~40줄입니다.
4. 도구를 다시 시작하고 훅을 확인합니다. Codex의 새 훅은 신뢰 검토가 필요합니다.

이미 있는 규칙과 설정을 파일째 덮어쓰지 않습니다. 실제 앱의 타입·린트·테스트 명령은 그대로 사용합니다.
배포·콘텐츠 제작·학습 문서는 목적에 맞게 유지하고 관련 작업에서만 읽습니다.

## JSDoc은 필요한 설명만

첫 문장은 결과나 책임입니다. 이름·타입만으로 부족한 계약만 덧붙입니다.

```ts
/**
 * 오래된 피드 앞부분을 제거하고 카드·페이지 인덱스를 함께 보정한다.
 * 유지된 카드의 페이지 위치는 보존하며 제거된 카드의 위치는 버린다.
 */
```

모든 함수에 강제하지 않습니다. 타입·전체 호출자·함수 목록·대략적 줄번호를 복제하지 않습니다.
중요한 이유는 해당 코드 옆에 남깁니다. 여러 파일이 함께 지킬 정책은 기능 문서에 둡니다.

## 훅의 범위

- 현재 작업 트리의 staged·unstaged·새 파일·삭제를 읽기 전용으로 확인합니다. 이동은 이전·새 경로로 처리합니다.
- `src/`의 코드·데이터 변경을 대상으로 하며 테스트 파일만 바뀌면 요청하지 않습니다.
- 기능 폴더와 같은 이름의 문서, 또는 변경 경로를 직접 언급한 기능 문서를 후보로 제시합니다.
- 공유 코드의 영향 문서를 모두 추론하지는 않습니다. 에이전트가 관련 흐름을 확인합니다.
- 기존 사용자 변경도 후보에 포함될 수 있습니다. 이번 작업의 변경만 점검합니다.
- `stop_hook_active`로 연속 점검을 막습니다. 문서 수정·새 문서 생성·커밋은 강제하지 않습니다.
- 훅이 직접 문서를 쓰거나 테스트를 실행하지 않습니다. 같은 에이전트가 필요한 갱신을 수행합니다.

```sh
node scripts/review-docs.mjs --check  # 변경 파일·문서 후보 확인
node --test                        # 하네스 자체 검증
```

공식 연결 규격: [Claude Code Hooks](https://code.claude.com/docs/en/hooks#stop), [Codex Hooks](https://learn.chatgpt.com/docs/hooks#stop), [Claude 문서 가져오기](https://code.claude.com/docs/en/memory#import-additional-files).
