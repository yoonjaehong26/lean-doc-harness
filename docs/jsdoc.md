# 파일과 주요 함수를 설명하는 JSDoc

파일을 열면 역할·사용처·주요 함수를 알 수 있고, 함수 앞에서는 동작과 계약을 알 수 있게 쓴다.
Manna의 파일 상단 안내와 주요 함수 설명을 기본으로 유지한다.

## 파일 상단: 파일의 지도
- 직접 작성한 JS/TS 파일에 `파일명 — 역할`, 필요한 배경, 사용처, 주요 함수/exports를 적는다.
- 사용처는 대표 소비자·계층을, 함수 목록은 실제 이름과 한 줄 역할을 쓴다. 큰 파일은 기능별로 묶는다.
- `'use client'` 등 지시문이 있으면 그 바로 다음, import보다 앞에 작성한다.
- 컴포넌트·훅·서버 모듈·모델·직접 작성한 설정·스크립트·테스트에도 적용한다.
- 자동 생성 파일은 제외한다. JSON·CSS 등 JSDoc을 지원하지 않는 형식에는 억지로 넣지 않는다.

## 주요 함수: 해당 동작의 설명
- 컴포넌트·훅·API 핸들러·서비스·주요 모델 함수·스토어 액션에 작성한다.
- 첫 문장에 결과·책임을 쓰고, 입력 의미·반환·실패·부작용·중요한 이유를 필요한 만큼 덧붙인다.
- `@param`, `@returns`, `@throws`에는 타입 반복 대신 단위·형식·실패 의미를 설명한다.
- 파일 안내는 전체 지도, 함수 주석은 구체적 계약이다. 같은 본문을 복사하지 않는다.

## 완성 예시
아래는 파일 전체 예시다. 앱 코드로 포함된 기능은 아니다.
```ts
/**
 * itemModel.ts — 항목 이름을 저장 가능한 형태로 정리한다.
 *
 * 입력 검증을 DB 접근과 분리해 브라우저·서버에서 같은 규칙을 사용한다.
 * 사용처: 항목 입력 폼, 서버의 항목 생성 처리.
 * 주요 함수/exports:
 * - normalizeItemTitle: 앞뒤 공백을 제거하고 빈 이름을 거절한다.
 */

/**
 * 항목 이름의 앞뒤 공백을 제거하고 빈 결과는 거절한다.
 * @param title - 호출자가 문자열로 검증한 원본 이름.
 * @returns 저장·표시에 사용할 이름. 내부 공백은 유지한다.
 * @throws {Error} 공백 제거 후 이름이 비어 있으면 발생한다.
 */
export function normalizeItemTitle(title: string): string {
  const normalized = title.trim();
  if (!normalized) throw new Error('이름을 입력해 주세요.');
  return normalized;
}
```

## 코드가 바뀌면 함께 맞춘다
- 함수 추가·삭제·이름 변경 → 파일 안내의 주요 함수 목록.
- 사용 계층·호출 경로 변경 → 파일 안내의 사용처.
- 입력·반환·부작용 변경 → 해당 함수 JSDoc. 프로젝트 판단 변화는 `.md`.
- 줄번호 목차는 쓰지 않는다. 중요한 이유·제약은 분량만을 이유로 지우지 않는다.
- 기존 주석의 오래된 사실은 현재 동작에 맞추고 보존할 이유·제약은 유지한다.
